# Collatz v2

Expanded Collatz family: four encodings × three step-function
bit-blastings × widths up to 64. v1 instances are left untouched.

## Encodings

| | shape | what SAT means | size |
|---|---|---|---|
| `unrolled` | `∀x ∃s_0..s_K` | every nonzero N-bit start reaches 1 in ≤K steps | O(K·N) |
| `succinct` | `∃f(x,t) ∀x,t,t'` | every nonzero start reaches 1 in <2^K steps | O(N+K), genuine DQBF |
| `tonly` | `∃f(t) ∀t,t'` | **some** start needs ≥2^K steps | O(N+K), \|U\|=2K |
| `indinv` | `∃Inv(s) ∀s,s'` (via `hwmc2dqbf_indinv`) | small starts (<2^⌈N/2⌉) never set the top bit | O(N) |

`tonly` flips the question — it searches for one *bad* trajectory rather
than asserting all trajectories converge — so its prefix is independent
of N.  `indinv` is the only encoding here whose SAT result is
mathematically interesting: it would prove the modular and integer
Collatz maps agree on the lower half of bv[N].

## Step variants

- `shift` — `3v+1` as `(v<<1)+v+1` (v1's choice)
- `mul`   — `3v+1` via a separate adder chain (`v + 2v + 1`)
- `shortcut` — odd ↦ `(3v+1)/2`, even ↦ `v/2` (the accelerated map;
  trajectories are ~⅔ shorter)

`shift` and `mul` are extensionally identical; they differ only in
clause structure.

## Why direct CNF, not EQFOB

`succinct`/`tonly`/`indinv` are emitted by a hand-rolled Tseitin builder
(`generate.py:_Cnf`) rather than EQFOB.  EQFOB's `fun` bitblast produces
formulas on which dqbdd/hqs and pedant **disagree** — see
`generate_test.py::test_eqfob_fun_disagreement` for a 146-var repro.
The direct-CNF versions are cross-checked against all three solvers and
a Python trajectory oracle at small N,K.  This also means **v1's
`succinct` instances are suspect**; left in place per family policy.
