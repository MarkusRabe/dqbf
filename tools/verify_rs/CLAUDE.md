# tools/verify_rs/ — second independent DQBF certificate checker (Rust)

A reimplementation of the trust boundary in Rust. Goals, in order:
correctness, **independence from `tools/verify/` and `provers/`**, speed.

## Why a second verifier

A verifier that accepts an incorrect proof manufactures false
confidence. Two independent implementations of the same spec, deriving
that spec only from the documentation (not from each other's code),
catch each other's bugs: a proof accepted by one but rejected by the
other points at a discrepancy in either the implementation or the
shared understanding of the spec. `cross_check_test.sh` enforces
agreement on every corpus case.

## Independence

This directory shares **no code** with `tools/verify/`, `core/`, or
`provers/`. It has its own DQDIMACS parser (`dqdimacs.rs`), AIGER
parser (`aiger.rs`), `.frp` parser (`frp.rs` — hand-rolled JSON, no
serde), and rule checks (`unsat.rs`, `sat.rs`). The only external
dependency is `flate2` for gzip and an external SAT solver for the
miter check (`kissat`/`cadical`/`satch`, same chain as the Python
verifier so the SAT-cert path has the same backend).

The implementation was derived from:
- `docs/references/dqdimacs.md` — DQDIMACS grammar
- `docs/references/fork_resolution_journal/main.tex` — the proof rules
  (Res §4.1, ∀Red §4.1, FEx §4.2, SFEx §6.2)
- `core/proof_trace.py` — the on-disk `.frp` JSON schema (data only)
- `tools/verify/CLAUDE.md` — the *interface* contract (CLI shape,
  symbol naming `u<id>`/`e<id>`, exit codes)
- the AIGER format spec (https://fmv.jku.at/aiger/FORMAT)

It was **not** derived from `tools/verify/{formats,unsat,sat}.py` or
`provers/frust/src/*.rs`.

## Spec decisions where the journal is ambiguous

These are the places where two independent readers of the journal could
implement differently. Documenting them keeps the verifiers in sync.

1. **Implicit ∀-reduction in `res` steps.** The `.frp` emitter (and
   Q-resolution in general) often fuses res+∀Red into one step. The
   `res` check accepts the claimed clause if it is the resolvent *or*
   a sound ∀-reduction of it. Rejecting strict equality would diverge
   on valid certificates.
2. **`ured` noop.** A `ured` step that drops nothing is rejected
   (signals a confused prover). The Python verifier accepts it; this
   is a documented Rust-stricter divergence (safe direction).
3. **`axiom` with spurious premises.** Rejected (suspicious metadata).
   Python accepts. Documented divergence.
4. **Symbol-table mismatch on a constant cone.** A `.aag` with `i0 u9`
   where `9` is not a universal is rejected even if no output's cone
   reads input 0. Python passes the cone check vacuously. Documented
   divergence — the strict reading is safe because a malicious cert
   can't hide a dependency behind a mislabelled input.
5. **Multiple universals dropped in one `ured`.** Allowed iff each
   dropped literal is individually justified relative to the *result*
   clause's `dep`. (The journal phrases the rule for a single literal;
   `dep(C)` for the result is the natural multi-drop generalisation.)
6. **FEx fresh-var re-use.** A second FEx step with the same `fresh`
   is accepted iff its `dep(x)` (computed from its own `part`) matches
   the first step's. This covers the prover emitting both halves as
   two `fex` steps sharing a `fresh` id.

## Build & run

```sh
cargo build --release --manifest-path tools/verify_rs/Cargo.toml
tools/verify_rs/target/release/dqbf-verify-rs sat   FILE.dqdimacs[.gz] CERT.aag [--solver PATH]
tools/verify_rs/target/release/dqbf-verify-rs unsat FILE.dqdimacs[.gz] PROOF.frp
```

Prints `VALID`/`INVALID`/`DEP-VIOLATION`. Exit 0 only on `VALID`.

## Tests

```sh
cargo test --manifest-path tools/verify_rs/Cargo.toml   # unit tests
tools/verify_rs/cross_check_test.sh                     # vs Python verifier
```

`tests/adversarial/` holds the deliberately-wrong corpus, generated by
`build_corpus.sh`. Each file maps to a risk in `RISKS.md`. The
cross-check fails iff the Rust verifier accepts something the Python
one rejects (the dangerous direction).

## Validation status

- 49 unit tests (`rules_test.rs` + `formats_test.rs`).
- 41-file adversarial + valid corpus; 38/41 agree with Python, 3
  Rust-stricter, **0 Rust-laxer**.
- 5/5 `tests/integration/tiny/` certs from `frust`: both VALID.
- 42/42 random_qbf instances with frust certs: both verifiers agree.
- ~9× faster than the Python verifier on the random_qbf sample.
