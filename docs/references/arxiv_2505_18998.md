# PdrER — Property Directed Reachability with Extended Resolution

## Citation

- **Luka, A., Vizel, Y.** *Property Directed Reachability with Extended
  Resolution.* 2025. [arXiv:2505.18998](https://arxiv.org/abs/2505.18998).

## Problem

PDR/IC3 (see `ic3_pdr.md`) proves safety by accumulating clauses, each
inductive relative to a frame. The clauses are derived by a sequence of
SAT calls; viewed as a proof, the run is a **Resolution** derivation —
every learned lemma is a clause over the *original* state variables,
obtained by resolving away conflicts. Resolution is the implicit proof
system of CDCL SAT, so PDR inherits its limits: there are properties
whose smallest inductive invariant is exponential as a CNF over the
original variables but polynomial if auxiliary definitions are allowed.
On those, PDR either times out or produces a huge invariant.

## Main idea

**Extended Resolution (ER)** augments Resolution with one rule: at any
point, introduce a *fresh* variable `e` together with the three clauses
encoding `e ↔ (ℓ_1 ∧ ℓ_2)` (or equivalently any binary gate). ER
p-simulates Frege systems and is exponentially stronger than
Resolution; the canonical separation is the pigeonhole principle, which
has polynomial ER proofs and only exponential Resolution proofs.

PdrER threads ER into PDR's lemma-generation step. When generalizing a
blocked cube, instead of only dropping literals (which keeps the lemma
a clause over original variables), PdrER may introduce an extension
variable `e` defined over a few state bits and learn a clause that
mentions `e`. The frames become CNFs over `x ∪ E` where `E` is a
growing set of extension variables, each with a fixed definitional
constraint that is added once to every frame. The frame invariants
(monotonicity, `F_i ∧ T ⇒ F_{i+1}'`, `F_i ⇒ P`) are preserved because
extension variables are definitionally determined by `x` — they add
expressiveness to the CNF *language* without adding reachable states.

The non-trivial part is *when* and *which* extension to introduce.
PdrER uses heuristics tied to generalization failure: when literal-
dropping stalls (the cube cannot be shrunk further but still recurs as
a CTI at many levels), the algorithm looks for a pair of literals in
the cube whose conjunction, named as `e`, lets generalization resume.
This is a structural cue rather than a global proof search.

## Results

On HWMCC 2019/2020/2024 benchmarks, PdrER solves more instances than
ABC's PDR within the same time limit, is faster on the commonly-solved
set, and uniquely solves a handful of instances that plain PDR cannot.
The paper reports modest extension-variable counts (tens, not
thousands) on the instances where ER helps — i.e., a few well-chosen
definitions suffice, consistent with ER's theory.

## Relation to fork resolution and this repository

The connection is direct. **Fork Extension is an Extended-Resolution
rule for DQBF.** FEx (and SFEx) introduce a fresh existential `x` with
definitional clauses `(C_1 ∨ x) ∧ (C_2 ∨ ¬x)` derived from a single
parent clause `C_1 ∨ C_2`; the soundness proof (journal Lemma 1)
constructs `x`'s Skolem function from the existing model — exactly the
"definitionally determined" property ER extension variables have. The
difference is the **dependency set**: FEx's fresh variable is an
existential with deps `dep(C_1) ∩ dep(C_2)`, so it is a *function* of
a restricted set of universals, not a propositional constant. SFEx
weakens that further by dropping universals via `C_3`.

So PdrER is the propositional/single-state-copy precedent for what an
IC3-style DQBF prover would do: run a frame-based invariant search;
when clause generalization stalls, introduce an FEx arbiter and
continue. Two design questions PdrER doesn't have to answer but we do:

1. **Dependency-set choice.** ER's `e` has no dependency restriction;
   FEx's `x` does. The PdrER heuristic ("name the conjunction of two
   stubborn literals") maps to "apply FEx with `part = {ℓ_1}`", which
   fixes deps as `dep(ℓ_1) ∩ dep(rest)`. Whether that's the right
   partition, or whether SFEx's `C_3` should be chosen to *minimise*
   deps, is open.
2. **Cross-frame reuse.** PDR pushes clauses forward across frames.
   FEx-introduced existentials are tied to a particular formula state
   (`g.n_vars` at introduction time). Reusing an arbiter `x` across
   frames means the frame formulas share a prefix extension — feasible
   if we treat the extensions as a global, monotonically growing prefix
   rather than per-frame.

PdrER is the strongest empirical evidence so far that
extension-style variable introduction is practical inside an
invariant-synthesis loop, not just inside a one-shot refutation. That
is the regime we want `provers/forkres/` to operate in once it moves
beyond naive saturation.
